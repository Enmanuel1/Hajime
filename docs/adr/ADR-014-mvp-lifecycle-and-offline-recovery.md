# ADR-014: MVP lifecycle and offline account recovery

Status: Accepted.

## Decision

Allow owner corrections only while training is RECORDED, with a required expected version and immutable
identity/provenance. Reuse the training-content invariants and catalog checks. Full replacement includes
optional dojo selection and child entries. Sharing/reviewing closes editing.

Expose explicit coach-only goal completion/cancellation, scoped to organization and ASSIGN_GOAL. Use an
ACTIVE/version-guarded SQL update and synchronous audit. Athletes read outcomes; the pilot has no self-
approval or reopening endpoint.

Password changes require current-password proof and revoke all sessions. Offline recovery uses one random
256-bit single-use code, generated by an authenticated account after password proof and saved externally
by the user. Only SHA-256 is stored. Code rotation replaces the old value; password change/recovery clears
it. Public recovery requires email plus the code; there is no email or administrator bypass. Credential
locks precede session locks across refresh and account security to prevent lock inversion. Rate limiting
covers recovery and password proof. Security events contain no credentials.

## Consequences

The pilot closes common journal/goal/account loops without AWS or email. Recovery depends on users saving
the code. Email ownership verification and email-based recovery remain separate. Exact CORS origins are
configurable; public TLS/proxy configuration still depends on deployment. A safe explicit backup/restore
script supports local recovery verification without creating a hosted workflow.
